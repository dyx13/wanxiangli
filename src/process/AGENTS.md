# process — 独立的真实进程会话

层：物理能力库。入口 `wanxiangli/process`，对象 `ProcessSession`。不导入 Work、Journal、组合者、宿主 SDK 或旧仓；Node使用原生 `node:child_process`，Bun使用原生 `Bun.spawn`。私有I/O适配不拥有公开会话状态，也不重试外部输入。这不是契约空壳，也不是宿主 canary。

## AXIOM
1. [使用者] 命令和输入会真的改变世界；启动、写入管道、退出是不同事实，不能重复执行或混称成功。
   - 理由：错把超时当作没有发生，会启动第二次；错把输出当作退出，会过早开始下一项工作。
2. [使用者、开发者] 长命令和大输出不能无限占用本进程内存；仍能交互、查看最近原始输出并明确知道哪些字节已丢弃。
   - 理由：留存全部输出和无人排空管道都可能使整个系统停住。
3. [开发者] 这项能力能脱离任务生命周期和宿主单独使用。
   - 理由：物理执行不需要认识阶段、评审、持久日志或模型请求。实际合作由外侧组织。

## LEMMA
1. [AXIOM 1, 3] 构造只启动一次；可执行文件、argv、工作目录、环境及容量显式给定，先校验全部输入再启动。不隐式开 shell、不重试、不读取宿主配置。
   - 推理：把隐含解释和默认环境移到调用方，输入才可以核对。传入绝对可执行路径可避免隐藏的 PATH 查找；调用 shell 时也必须显式指定。
2. [AXIOM 1] `started` 只确认启动；`wait` 等到直接子进程退出且输出管道关闭。到期只返回 TimedOut，既不发信号也不宣布退出。`signal` 在直接子进程尚未观察到退出时，向自己的 POSIX 进程组发信号，返回请求结果，不等于退出。
   - 推理：原生 spawn、exit、close 分别有各自的事实范围，不能用一个替代另一个。直接子进程已退出后不再向旧 PGID 发信号，避免把过期身份当新许可。
3. [AXIOM 1, 2] stdin 一次最多一个有界写入，成功只代表全部字节取得原生管道写入确认，不代表子进程处理完成。Node等待write回调，Bun等待FileSink确认全部字节及flush；部分写入、错误或确认前退出保持 Unknown，不自动补写。
   - 推理：不受控队列会绕过内存预算；发生过多少外部消费不能由一次管道错误猜出。
4. [AXIOM 2] stdout、stderr 分别有固定容量环形缓冲和独立字节游标；持续排空，不依赖读者。原始字节不变，返回副本；溢出只丢最早部分，不杀进程。文本视图跳过切口半个 UTF-8 字符，未结束时暂留尾部未齐字节；内部非法编码则不给伪造文本。
   - 推理：按字节界定留存和缺口才能逐次读取。两条管道各自有序，不声称两者合并后的真实因果顺序。文本是明确区间的视图，不是替换原始输出。
5. [AXIOM 1, 3; 根 LEMMA 3, 4] 句柄、缓冲、活动写入与等待登记由对象私有持有；每个等待在到期或关闭时清理自己的定时器和登记，不靠全局状态或公开原生句柄维护不变量。
   - 推理：多实例相互隔离，外侧只使用公开消息；没有生命周期对象和存储替身也能运行并验证。
6. [AXIOM 1, 2, 3] 完整输出使用显式Capture模式：消费者逐块拉取原始字节，最多一个待决读取，每块不超过64KiB。Node使用原生pipe；Bun使用独立非阻塞FIFO读端与阻塞写端，按Readable的pull请求及有限预取读取，真实EAGAIN只重试当前读取，真实正长度read返回零才确认EOF。每路Readable队列最多128KiB，另有一个64KiB私有scratch和最多一个重试任务；成功只复制实际字节，不覆盖已交付buffer。显式discard撤销重试并关闭私有读fd。公共observed=0不等于fd未读。默认留尾模式继续独立成立。
   - 推理：任何有限容量尾部和定时轮询都可能丢字节，不能据此承诺完整输出。磁盘由外侧组合者处理，库只拥有物理管道；消费者失败可明确放弃输出，放弃不等于进程退出。

## SPEC
1. [LEMMA 1] 非法路径、字段、容量、argv、环境和访问器在 spawn 前拒绝；原生启动失败保留错误，不生成退出码零或发起重试。
   - 证明：`tests/001.test.mjs` 已通过真实命令、参数原样传递、显式环境、特殊环境键及 ENOENT；非法输入同时观察原生 spawn 入口为零次调用。
2. [LEMMA 3, 5] 有界 stdin 写入、忙时拒绝、关闭输入幂等、输入副本隔离及 EPIPE 不重试。
   - 证明：`tests/002.test.mjs` 已通过真实 echo、二进制输入、背压、EOF、提前关管道及错误返回值别名反例。
3. [LEMMA 4] 双路留存量各不超过 tailBytes，read 不消费共享游标；缺口精确。字节与文本边界分别报告，二进制不会被静默替换。
   - 证明：`tests/003.test.mjs` 已通过约 9 MiB 输出、十种容量切口、环形回绕、拆分 UTF-8、非法字节、零预算与多读者。每路 1 KiB 留存时仍排空大输出；未测量完整 RSS，不把留存预算冒称全部进程内存预算。
4. [LEMMA 2, 5] 等待超时不改变进程；多个等待互不取消；SIGTERM 被忽略时仍不宣称结束，SIGKILL 向同组后代传播；exit 后管道未闭仍是 Draining。
   - 证明：`tests/004.test.mjs` 已通过真实子进程和孙进程、明确就绪屏障、150 个独立超时等待与长等待清理、TERM 忽略后 KILL、exit 后管道保持打开。公开等待数值先验原值再转换，反例拒绝字符串、小数和越界值，不能被 Fable 的 int 转换绕过。
5. [LEMMA 5] 公开生成对象不暴露原生句柄与缓冲；输入和返回值不泄漏可变别名。只携带 process 源码即可编译并跑本库测试，安装包在没有其他入口文件时仍可运行。
   - 证明：`tests/005.test.mjs` 的实际生成对象及多实例测试通过；`scripts/tests/build.test.mjs` 仅提供 process 源码时编译并运行全部 49 项本库测试。`scripts/tests/process-package.test.mjs` 实际安装 tarball 后删除全部第一刀产物，在 Node 25.9.0、Bun 1.3.14 / Linux 上分别通过 stdin、大输出和真实进程组信号场景。
6. [LEMMA 6] Capture保全双路字节与各自游标，暂停消费者时实际写者受背压，空闲读取不得占住异步I/O线程。启动/读取失败可见，显式放弃及时释放待决读取及私有fd，不写入退出事实。仅块大小或observed=0不足以证明，总RSS也不由输出缓冲上限推导。
   - 证明：`tests/006.test.mjs` 在 macOS / Node 26.6.0、Bun 1.3.14 分别 7/7，通过真实双路大输出、慢消费者、返回字节隔离、重叠读取、主动放弃、ENOENT、SIGKILL 及实际 stdout error 事件注入；后者不是设备 I/O 故障实测。Node Process/Supervision 69/69，Bun Capture/Supervision 19/19；Bun 全部 Process/Supervision 另有四项平台与夹具失败，见施工顺序，未声称全绿。此前独立安装 tarball 的 Node/Bun 双路 32 MiB 及 TypeScript 证据保留。没有测量完整 RSS，不把块大小等同全部内存；Draining 监管不在本能力内。

Process/Supervision的Node和Bun各70/70，包含真实spawn观察正控、非法输入零spawn、特殊环境键、宿主哨兵隔离、二进制stdin、目标确切读取一字节后未确认大写入被杀、真实POSIX断管及Capture/同组监管。旧Bun child_process的回调可在目标处理前成功，不能以杀进程倒推失败；旧fd0夹具也没有建立真实断管。新反例先建立物理前提，再检查Unknown/EPIPE，不接受任一结果、不自动补写。

## 边界与草稿重判

- 本次实现POSIX pipe进程，不是PTY、容器或操作系统沙箱。Node/Bun每个平台分别验收，不能沿用旧版本Linux结果替代新Bun FIFO路径；Bun需要/usr/bin/mkfifo与临时FIFO。实际平台证据见施工记录，Windows在启动前拒绝。
- 关闭只证明直接子进程及本对象的管道已收尾，不证明所有后代已终止。逃离进程组、关闭继承管道后继续运行的守护进程以及父程序崩溃后的托管需要更强的外部监管，本库不冒称支持。
- 调用方负责 `endInput` 或显式信号及最终等待；没有析构器自动杀进程，也不以等待超时自动重发命令。进程尚未退出时可升级信号；观察到退出后拒绝使用旧进程组身份。
- 默认留存是有界尾部；Capture 提供有背压的完整字节交接，但不提供完整持久日志。Spool 与 PTY 暂不建立，磁盘能力仍由组合者协调。
- 草稿中的“物理执行只能在 host-omp”和“契约不能有实例”撤回：这会使独立物理能力只能等待宿主。全局 LargeGate 也不预建；跨进程会话的容量协调是组合者职责。
- 第二刀在新仓完成独立能力，不据此宣称替换了旧进程实现。本次不读取、不修改原仓。
